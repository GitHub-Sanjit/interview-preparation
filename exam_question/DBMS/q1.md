# Question 1: Foreign Key in the Bookings Table (Interview Preparation Notes)

## 🎯 Interview Question

**Question 1:**

What role does a Foreign Key play in the Bookings table, and how does it safeguard against entering a ticket sale for a match that doesn't exist?

---

# 1. What is a Foreign Key?

A **Foreign Key (FK)** is a column or a group of columns in one table that refers to the **Primary Key (PK)** of another table.

Its main purpose is to establish and enforce relationships between tables.

It ensures that the values stored in the child table must already exist in the parent table.

---

## General Syntax

```sql
FOREIGN KEY (column_name)
REFERENCES ParentTable(primary_key_column)
```

---

# 2. Foreign Keys in the Football Ticket Booking System

Suppose we have the following tables:

## Matches Table

```sql
CREATE TABLE Matches (
    match_id SERIAL PRIMARY KEY,
    home_team VARCHAR(100),
    away_team VARCHAR(100),
    match_date DATE
);
```

---

## Bookings Table

```sql
CREATE TABLE Bookings (
    booking_id SERIAL PRIMARY KEY,

    user_id INTEGER NOT NULL,
    match_id INTEGER NOT NULL,

    FOREIGN KEY (user_id)
        REFERENCES Users(user_id),

    FOREIGN KEY (match_id)
        REFERENCES Matches(match_id)
);
```

---

# 3. What Role Does the Foreign Key Play in the Bookings Table?

The Foreign Key ensures that every booking is linked to:

- An existing user
- An existing match

The relationship is:

```
Users (1) --------< Bookings >-------- (1) Matches
```

Meaning:

- One user can make many bookings.
- One match can have many bookings.
- Every booking must belong to one valid user and one valid match.

---

# 4. How Does It Prevent Booking a Non-Existent Match?

Suppose the Matches table contains:

| match_id | Home Team | Away Team |
|-----------|------------|------------|
| 1 | Barcelona | Real Madrid |
| 2 | Liverpool | Arsenal |

---

## Valid Booking

```sql
INSERT INTO Bookings (user_id, match_id)
VALUES (5, 1);
```

This works because:

```
match_id = 1
```

already exists in the Matches table.

---

## Invalid Booking

```sql
INSERT INTO Bookings (user_id, match_id)
VALUES (5, 100);
```

Assume:

```
match_id = 100
```

does NOT exist in Matches.

The database will reject this insertion.

Example error:

```text
ERROR:
insert or update on table "Bookings"
violates foreign key constraint

Key (match_id)=(100)
is not present in table "Matches".
```

Therefore:

❌ Ticket sale is prevented.

---

# 5. Why Is This Important?

Without Foreign Keys:

The database would allow:

| booking_id | user_id | match_id |
|------------|----------|-----------|
| 1 | 5 | 100 |

But Match 100 does not exist.

This creates:

## Orphan Records

Definition:

An orphan record is a child record that references a parent record that does not exist.

Example:

```
Bookings
     ↓
match_id = 100

Matches Table:
No Match 100 exists.
```

This causes:

- Inconsistent data
- Incorrect reports
- Invalid ticket sales
- Application errors

---

# 6. Referential Integrity

Foreign Keys enforce a concept called:

## Referential Integrity

### Definition:

Referential integrity ensures that relationships between tables remain valid and consistent.

It guarantees that:

> Every foreign key value must match an existing primary key value in the referenced table.

---

Example:

```
Bookings.match_id
        ↓
Must exist in
Matches.match_id
```

If not:

```
Insertion → Rejected
Update → Rejected
Deletion → Controlled
```

---

# 7. What Happens During DELETE?

Suppose:

```sql
DELETE FROM Matches
WHERE match_id = 1;
```

But bookings already exist for Match 1.

The Foreign Key determines what happens.

---

## Option 1: RESTRICT (Default)

```sql
FOREIGN KEY (match_id)
REFERENCES Matches(match_id)
```

Result:

❌ Cannot delete the match.

Error occurs.

---

## Option 2: CASCADE

```sql
FOREIGN KEY (match_id)
REFERENCES Matches(match_id)
ON DELETE CASCADE
```

Result:

```
Delete Match
      ↓
Delete Related Bookings Automatically
```

---

## Option 3: SET NULL

```sql
FOREIGN KEY (match_id)
REFERENCES Matches(match_id)
ON DELETE SET NULL
```

Result:

```
Match Deleted
       ↓
Bookings.match_id = NULL
```

Only possible if NULL is allowed.

---

# 8. Why Is Foreign Key Important in Real Life?

In a football ticket booking system:

Without Foreign Keys, the system could:

❌ Sell tickets for matches that were cancelled.

❌ Sell tickets for matches that never existed.

❌ Generate inaccurate revenue reports.

❌ Cause customer confusion.

With Foreign Keys:

✅ Every booking corresponds to a real match.

✅ Database consistency is maintained.

✅ Invalid transactions are prevented.

✅ Business rules are enforced automatically.

# 9. Common Interview Questions and Answers

## Q1: What is a Foreign Key?

### Answer:

A Foreign Key is a column in one table that references the Primary Key of another table to establish relationships and maintain referential integrity.

---

## Q2: Can a Foreign Key contain duplicate values?

### Answer:

Yes.

Multiple bookings can reference the same match.

Example:

| booking_id | match_id |
|------------|-----------|
| 1 | 5 |
| 2 | 5 |
| 3 | 5 |

This represents many bookings for one match.

---

## Q3: Can a Foreign Key contain NULL values?

### Answer:

Yes, unless the column is defined as NOT NULL.

Example:

```sql
match_id INTEGER NOT NULL
```

Then NULL is not allowed.

---

## Q4: What happens if you insert a Foreign Key value that doesn't exist?

### Answer:

The database rejects the operation with a Foreign Key constraint violation error.

---

## Q5: What is Referential Integrity?

### Answer:

Referential integrity ensures that every Foreign Key value matches an existing Primary Key value in the referenced table.

---

## Q6: Difference Between Primary Key and Foreign Key?

| Primary Key | Foreign Key |
|-------------|-------------|
| Uniquely identifies a row | References another table's Primary Key |
| Cannot contain NULL | Can contain NULL (unless restricted) |
| Must be unique | Can have duplicate values |
| One per table | Multiple allowed per table |
