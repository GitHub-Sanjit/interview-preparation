# Question 1: Foreign Key in the Bookings Table (Interview Preparation Notes)

## 🎯 Interview Question

**Question 1:**

What role does a Foreign Key play in the Bookings table, and how does it safeguard against entering a ticket sale for a match that doesn't exist?

---

# 1. Understanding the Bookings Table in Our System

In our Football Ticket Booking System, the **Bookings** table stores information about ticket purchases made by users.

```sql
CREATE TABLE Bookings (
    booking_id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    match_id INTEGER NOT NULL,
    seat_number VARCHAR(20),
    payment_status VARCHAR(20),
    total_cost DECIMAL(10,2),

    FOREIGN KEY (user_id)
        REFERENCES Users(user_id),

    FOREIGN KEY (match_id)
        REFERENCES Matches(match_id)
);
```

The table contains two Foreign Keys:

* `user_id` → references `Users(user_id)`
* `match_id` → references `Matches(match_id)`

---

# 2. What is a Foreign Key?

A **Foreign Key** is a column in one table that references the **Primary Key** of another table.

Its purpose is to create relationships between tables and maintain **referential integrity**.

In our database:

```text
Users
   ↓
Bookings
   ↑
Matches
```

The Bookings table acts as a bridge connecting users and matches.

---

# 3. Role of Foreign Key in the Bookings Table

The Foreign Keys ensure that:

### For `user_id`

Every booking must belong to an existing user.

```text
Bookings.user_id
       ↓
Users.user_id
```

---

### For `match_id`

Every booking must refer to an existing match.

```text
Bookings.match_id
       ↓
Matches.match_id
```

This means the system cannot create a booking unless both the user and match already exist.

---

# 4. How Does It Prevent Selling Tickets for Non-Existent Matches?

Assume the Matches table contains:

| match_id | fixture             |
| -------- | ------------------- |
| 1        | Brazil vs Argentina |
| 2        | Spain vs Germany    |
| 3        | England vs France   |

---

## Valid Booking Example

```sql
INSERT INTO Bookings
(user_id, match_id, seat_number, payment_status, total_cost)

VALUES
(5, 2, 'A15', 'Confirmed', 1500);
```

Why is this valid?

Because:

```text
match_id = 2
```

exists in the Matches table.

The booking is successfully created.

---

## Invalid Booking Example

```sql
INSERT INTO Bookings
(user_id, match_id, seat_number, payment_status, total_cost)

VALUES
(5, 100, 'A15', 'Confirmed', 1500);
```

Suppose:

```text
match_id = 100
```

does NOT exist in Matches.

The database rejects the insertion.

Example error:

```text
ERROR:
insert or update on table "Bookings"
violates foreign key constraint

Key (match_id)=(100)
is not present in table "Matches".
```

Result:

❌ Ticket sale is blocked.

---

# 5. Why Is This Important?

Without the Foreign Key constraint, the database would allow:

| booking_id | user_id | match_id |
| ---------- | ------- | -------- |
| 1          | 5       | 100      |

However:

```text
Match 100 does not exist.
```

This creates invalid data.

Possible problems include:

* Selling tickets for matches that were never scheduled.
* Incorrect booking records.
* Wrong revenue calculations.
* Customer confusion.
* System inconsistencies.

---

# 6. Referential Integrity

Foreign Keys enforce **Referential Integrity**.

## Definition

Referential Integrity means:

> Every Foreign Key value must match an existing Primary Key value in the referenced table.

In our system:

```text
Bookings.match_id
        ↓
Must exist in
Matches.match_id
```

If it does not exist:

* INSERT fails.
* UPDATE fails.
* Database consistency is preserved.

---

# 7. Parent Table and Child Table

In this relationship:

## Parent Table

```text
Matches
```

because it provides the Primary Key.

---

## Child Table

```text
Bookings
```

because it contains the Foreign Key.

Relationship:

```text
Matches (Parent)
      1
      |
      |
      ∞
Bookings (Child)
```

One match can have many bookings.

Each booking belongs to exactly one match.

# 8. Real-World Importance in Our Football Ticket System

Without Foreign Keys:

❌ Fans could purchase tickets for matches that do not exist.

❌ Reports could show fake ticket sales.

❌ Revenue calculations would become inaccurate.

❌ Data inconsistency would increase.

---

With Foreign Keys:

✅ Only valid matches can be booked.

✅ All ticket sales correspond to real matches.

✅ Data integrity is maintained.

✅ Business rules are enforced automatically.

# 9. Common Interview Questions and Answers

## Q1: What is a Foreign Key?

### Answer:

A Foreign Key is a column that references the Primary Key of another table to establish relationships and enforce referential integrity.

---

## Q2: What does the `match_id` Foreign Key do in Bookings?

### Answer:

It ensures that every booking refers to an existing match in the Matches table.

---

## Q3: What happens if a booking references a non-existent match?

### Answer:

The database rejects the operation with a Foreign Key constraint violation error.

---

## Q4: What is Referential Integrity?

### Answer:

Referential Integrity ensures that Foreign Key values always correspond to existing Primary Key values in the referenced table.

---

## Q5: Can multiple bookings have the same `match_id`?

### Answer:

Yes.

Many fans can book tickets for the same match.

Example:

| booking_id | match_id |
| ---------- | -------- |
| 1          | 2        |
| 2          | 2        |
| 3          | 2        |

This represents a One-to-Many relationship.

---

## Q6: What type of relationship exists between Matches and Bookings?

### Answer:

One-to-Many.

One match can have many bookings, but each booking belongs to one match.

---

# 10. Ideal Viva Answer (45–60 Seconds)

"In the Bookings table, the Foreign Key `match_id` references the Primary Key `match_id` in the Matches table. Its role is to maintain referential integrity by ensuring that every booking is associated with a valid existing match. If someone tries to create a booking using a match_id that does not exist in the Matches table, the database automatically rejects the operation with a Foreign Key constraint violation error. This prevents invalid ticket sales, avoids inconsistent data, and ensures that tickets can only be sold for legitimate matches in the system."
